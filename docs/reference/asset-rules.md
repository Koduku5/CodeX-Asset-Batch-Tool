## 核心定义

把一个资产定义为“一项需要独立交付、能够被后续镜头复用的稳定视觉参考目标”。先判断是否需要资产，再判断交付目标是什么；不要先看名词属于人、动物还是物件。

五个 Sheet 表示五条**视觉制作路线**，不表示剧情身份。角色、生物或机器即使在剧情中都是有姓名、有台词的“角色”，也要按主要视觉设计任务进入对应 Sheet。规范名称写入 `assetName`；所有类别的剧情身份与硬事实写入 `scriptSetting`；只有角色、生物和群演的归属写入 `faction`。场景和道具没有 `faction`，尤其不能给道具型机械新增该字段。

同一交付目标只能进入一个 Sheet。只有确实需要两张不同用途的参考图时，才把“具体个体”和“群体标准”、“穿戴者完整造型”和“独立服装设计”等建立为两个名称与用途明确的资产。

## 四步判定

### 1. 判断是否需要独立资产

对象必须在成片画面中实际可见，或通过照片、壁画、屏幕、投影、雕像等媒介形成可辨识的视觉呈现；同时，现有资产与普通镜头提示词不足以稳定复现它。再至少满足以下一项才登记：

- 需要跨镜头或跨集保持同一主体、结构、造型或空间身份。
- 轮廓、解剖、服装体系、机械结构或空间布局具有专属设计，纯文字临场生成容易漂移。
- 会被近距离展示、操作、穿戴、进入、破坏或作为关键叙事信息读取。
- 是可重复使用的物种标准、群体视觉体系、场景模块或装备体系。
- 虽只出现一次，但该画面的清晰度、复杂度或一致性要求使其必须先有参考图。

以下条件本身都不能决定纳入：是否有台词、是否有姓名、剧情地位高低、出现集数多少、状态持续时间长短。

只在台词或旁白中被提到、完全不形成画面的对象不登记。通用背景、普通物件、完全不需要控制外观的模糊背景路人，或能够可靠依附现有参考图并用镜头提示词表达的轻微状态不登记；在 `exclusions` 记录有价值的排除判断。

### 2. 确定交付粒度与剧情身份

先明确本次真正要交付的是哪一种参考目标：

- 需要专属稳定视觉身份、不可互换的具体单体。
- 不需要专属视觉身份的可替换单人 NPC 或群体视觉体系。
- 可调度或可观察的空间环境。
- 可从主体中分离制作的物件、设备、载具或服装。

再判断剧情身份是具体个体、群体、环境还是物件。这个判断用于命名、归并和填写剧本设定，不直接决定 Sheet。

有台词的普通守卫如果仍可被同制服人员替换，就不是角色；只要画面需要控制其外观，单独出现也进入群演。有姓名的龙即使是剧情主角，如果主要制作难点是非人解剖，仍走生物路线。无法判断人物是否需要专属视觉身份时，先写待确认，不要提前建错资产。

### 3. 选择视觉制作路线

严格按“主要交付物是什么、制作时首先需要解决什么”选择一个 Sheet，具体标准见下节。发生冲突时使用以下裁决顺序：

1. 先看最终参考图解决的是专属单体身份、可替换 NPC/群体、空间还是独立物件。
2. 单体再看主要设计难点是人形表演与完整穿搭、非人解剖，还是机械/载具结构。
3. 从属元素不改变主资产类别；只有需要独立交付时才另建资产。
4. 仍无法唯一判断时写入待确认，禁止跨 Sheet 重复登记来规避判断。

### 4. 判断是否需要新形态

不要使用“长期才拆、短期不拆”。只问：继续沿用旧参考图，能否在不互相冲突的提示词下稳定复现新画面？不能就拆，能就不拆。

## 五类制作路线

### 角色

- 登记必须维持专属稳定视觉身份、不可互换的具体单体，且主要制作任务是人形比例、脸部识别、发型、完整穿搭与人形表演。
- 人类、拟人主体、人形外星种族、人形仿生人或人形机器人都可进入角色；物种名称或科幻身份不能自动把它们改到生物或道具。
- 姓名、台词或剧情行为只能证明其可能具有独立身份，不能替代“是否需要独立参考图”的纳入判断。
- 命名使用“主体名称（形态或造型）”，例如“使者甲（常服造型）”。

### 生物

- 登记具体生物个体或物种标准，且主要制作任务是非人解剖、肢体结构、运动方式与皮毛、鳞片、甲壳等表面系统。
- 动物、怪物、非人形外星生物和幻想生物通常进入生物；有姓名、台词、阵营或主角身份也不改变其制作路线。
- 人形种族若主要靠人形体态、脸部和服装区分，进入角色；不要因为“外星”“妖怪”“兽人”等称谓一律放入生物。
- 群体交付目标进入群演；只有单体或物种标准本身需要独立解剖参考时，才另建生物资产。
- 命名使用“主体名称（形态）”或“物种名称（标准形态）”。

### 群演

- 登记不需要专属视觉身份、可以由同功能主体替换的普通单人 NPC，以及可互换使用的群体视觉体系；仍使用同一个群演类别，不拆子类型。
- 单人 NPC 主要交付岗位、功能和场合所需的完整外观范围，不固定为某张专属面孔；群体主要交付共同轮廓、制服或表面规律，以及必要成员差异和候选变体。
- 群演不限于人类：前台、服务员、普通守卫、学生、工作人员等单人 NPC，以及人群、异族军队、兽群、机械队列和机器人劳工都可进入群演。
- 如果一群主体只需复制同一张单体或物种标准参考图，没有独立的成员分型、制服体系或群体差异，就沿用该单体资产，不再建立群演；只有群体体系本身需要设计时才登记。
- 有名字、台词、单独镜头或一次动作的普通 NPC，只要仍可由同功能主体替换，画面需要控制外观时就进入群演；只有无法辨识且不需要控制外观的纯背景人员才不登记。
- 具体首领、固定个体或需要独立连续性的成员，按其主要视觉任务另建角色、生物或道具资产。
- 纯背景、无法辨识且无需统一视觉体系的人群或兽群不登记。

### 场景

- 登记实际承载画面、需要稳定空间设计的地点、建筑空间、自然环境、标志性地貌或可复用环境模块。
- 判断重点是空间布局、固定结构、调度关系和环境视觉身份，而不是该地点出现了多久。
- 地点通过照片、屏幕、壁画、记忆画面或远景清楚呈现，并且需要稳定设计时仍可登记；只在对白中提及则不登记。
- 通用蒙太奇背景且可由普通提示词稳定生成时不登记；一次性但结构复杂、需要明确视觉信息的空间仍可登记。

### 道具

- 登记可以从角色或场景中分离制作的物件、武器、工具、家具、设备、载具、机器、机甲、机械主体、服装或可穿戴装备。
- 剧情上具有意识或姓名的机械主体，如果主要制作任务是机械结构、零件连接或载具形态，仍走道具路线；以人形身体、脸部与穿搭为主要任务的人形机器人进入角色。
- 与单一角色绑定的日常服装默认属于角色造型；完整礼服、盔甲或制服只在需要独立展示、多人复用或作为单独设计交付时建立道具资产。
- 载具内部可调度空间若需要独立场景参考，建立场景；载具外观本体仍是道具。两者是不同交付物，不属于重复登记。

## 形态拆分

满足以下任一情况，并且旧参考图无法稳定承载时，建立新形态：

- 单体的整体轮廓、身体比例、解剖结构或完整服装体系发生显著变化。
- 生物发生变身、成长、机械化或其他改变主要身体结构的阶段。
- 群体的共同制服、物种形态、阶层构成或稳定视觉体系整体改变。
- 场景的空间布局、固定结构或核心视觉身份发生改变，例如坍塌后成为另一套可调度空间。
- 道具的结构、展开方式、功能形态或主要构造发生改变。
- 主体的稳定材质、主配色或表面身份发生足以改变整体辨识的系统性变化。
- 一次性礼仪造型、伪装、战斗形态或灾后状态虽然持续很短，但需要一张独立完整参考图才能制作。

以下通常不拆：表情、姿态、镜头光照、普通天气、轻微污损、湿润、局部血迹、可由已有资产加提示词稳定表现的临时伤势，以及不改变整体造型的少量可拆附件。

后文只是补充该形态从一开始就存在的视觉信息时，回填原资产。剧情事件后来造成的新视觉形态时，建立新资产，不把结果倒填到早期形态。跨 Sheet 的不同形态使用不同的完整 `assetName`，例如“迦罗（人形）”与“迦罗（兽化形态）”；不要把同一个完整名称复制到两个 Sheet。

## 从属元素与画中呈现

- 宠物、纹样、徽章、手持物、场景陈设或角色装备默认保留为主资产的从属元素。
- 从属元素需要特写、被独立操作或转交、跨多个主体复用，或其自身结构必须保持一致时，再单独建资产。
- 画中画对象只按实际可见清晰度判断。新闻屏幕上一闪而过的模糊城市不建；需要读出地标身份并反复出现的城市画面可建场景。
- 区分媒介内容与媒介载体：屏幕中的人物、城市或生物按内容本体的制作路线判断；电视、相框、照片实物或投影设备只有自身也需要独立设计时才另建道具。
- 壁画、海报或照片中的形象若只是所属物件的图案，不自动把图中主体另建资产；只有图中主体还需要跨媒介或实体形态保持同一视觉身份时才独立登记。
- 动态效果、界面元素、瞬时能量和纯环境现象不建立特效 Sheet；只有其中存在必须独立复用的稳定实体时，才按实体本身归类。

## 边界案例

| 对象 | 正确判断 |
|---|---|
| 有姓名、会说话的四足龙王 | 剧情身份是具体角色；主要制作难点是非人解剖，进入生物 |
| 人形狐族使者 | 若主要靠人形体态、脸部与穿搭塑造，进入角色 |
| 一队外星难民 | 若交付群体共同形态与必要差异，进入群演 |
| 外星种族标准解剖 | 若交付单体物种标准，进入生物 |
| 无特殊分型的一群同种狼 | 只需复用同一物种标准时，仅建立一个生物资产，不重复建立群演 |
| 具有工兵、卫兵、祭司三级构成的虫族军团 | 群体体系进入群演；命名统领需要独立解剖参考时另建生物 |
| 只说一句话的制式守卫 | 可互换时不建角色；需要统一设计则进入群演 |
| 单独出镜并说话的酒店前台 | 不需要固定面孔、可由同岗位人员替换时进入群演；需要观众跨镜头认出同一个人时进入角色 |
| 只出现一集的登基礼服 | 需要穿戴者完整新造型时拆角色形态；需要独立服装设计或复用时进入道具 |
| 具有人格的坦克型 AI | 剧情身份是角色，但主要交付机械/载具结构，进入道具 |
| 具有人格的人形仿生人 | 主要交付人形身体、脸部与穿搭时进入角色 |
| 机甲外观、独立驾驶舱与驾驶员 | 分别是道具、场景和角色，三者对应不同参考图 |
| 只出现一个镜头的灾后城市 | 若空间结构已经改变且旧场景图无法承载，拆出场景新状态 |
| 仅由对白提到的首都 | 不登记；若通过屏幕或远景清楚呈现且需要稳定地标设计，则登记场景 |

## 设计补全与排序

先提取剧本硬设定，再依据世界观事实中与当前资产相关的全局约束补全生成必需的通用视觉信息。按 [prompt-writing.md](prompt-writing.md) 达到对应制作路线的核心成像完整度；不得把推测升级为剧情事实，也不得为了让分类看起来合理而新增身份、能力、功能或后续剧情约束。

各 Sheet 按首次实际需要该独立参考图的集数和本集内首次需求顺序排列，不按剧情地位、出现次数或形态持续时间排序。仅被提及不等于实际制作需求。

五类资产分别使用 `CHAR`、`CREATURE`、`CROWD`、`SCENE`、`PROP` 前缀。同步脚本按首次制作顺序自动编号，`EP` 后缀取 `firstRequiredEpisode`。

## 提交前自检

1. 该对象是否真的需要一张可独立交付的稳定参考图？
2. 最终交付是在固定专属单体身份、可替换 NPC/群体、空间还是独立物件？
3. Sheet 是否由主要视觉制作任务决定，而不是被姓名、台词、物种称谓或剧情地位误导？
4. 若与其他资产同时登记，两者是否确实对应不同参考图，而非同一对象重复分类？
5. 新形态是否因为旧参考图无法稳定复现，而不是只因为“换了一集”或“持续很久”？
6. 无法唯一判断的项目是否进入待确认，而没有擅自归类？

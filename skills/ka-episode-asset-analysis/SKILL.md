# KA 剧本资产拆分规则

本契约只用于一集剧本的语义分析。拆分、文件写入、累计合并、资产 ID 分配、进度和锁全部由固定脚本负责；单集 Agent 不执行也不解释这些步骤。

## 允许读取的输入

- 当前 `cache/单集原文/第NNN集.json`。
- 当前 `cache/累计记录/世界观记录.json`。
- 从本集提取候选主体名称后，通过固定查询命令返回的命中旧资产完整记录。
- 只有候选归并发生歧义时，才查询轻量名称与别名索引。

禁止读取其他集原文、五类累计资产全集、全剧总览、Excel、出图队列、提示词配置和生产脚本源码。

## 世界观事实

`scriptAnalysis` 只写本集新增或修订的稳定世界观事实。候选必须由原文直接陈述或多处明确线索唯一导出，并且跨场景持续成立或具有清楚的历史阶段边界；删除它会使世界机制、组织关系、能力边界、资源流通或稳定视觉约束无法解释。

排除题材标签、剧情流水、情绪与主题评价、类型常识、一次性策略、资产局部外观和没有原文依据的推测。

- `item` 固定写成 `具体锚点｜规则维度`，只使用一个全角 `｜`。左侧是剧本中的具体主体，右侧是本条事实描述的机制或关系。
- `content` 是可独立理解的完整命题，保留原文已有的条件、范围、门槛、代价、例外、后果和阶段边界；不得提“本集”“剧本”“分析过程”或内部文件。
- 更新同一语义命题时提交保留旧有效信息的完整整合版，禁止用本集增量覆盖历史事实。冲突无法唯一解释时不覆盖旧事实，写入 `exclusions`。

## 资产纳入与分类

资产是“需要独立交付、能被后续镜头复用的稳定视觉参考目标”。对象必须在画面中实际可见或通过媒介形成可辨识呈现，并且现有参考资产与普通镜头描述不足以稳定复现；同时至少满足跨镜头一致性、专属轮廓或结构、关键近景/操作、可复用体系，或一次性复杂画面必须先有参考图中的一项。

只被提及、通用背景、普通物件、完全不需要控制外观的模糊背景路人、瞬时界面/能量/特效，以及可由旧资产加普通描述稳定表现的轻微状态不建立资产；有价值的排除判断写入 `exclusions`。

五个数组表示视觉制作路线，不表示剧情身份；同一交付目标只能进入一个数组：

- `characters`：具有专属、稳定视觉身份且不可互换的人形单体，主要解决脸部识别、人形比例、发型、完整穿搭和表演。
- `creatures`：非人解剖单体或物种标准，主要解决肢体、运动和皮毛/鳞片/甲壳等表面系统。
- `extras`：不需要专属视觉身份的可替换单人 NPC 或群体；单人交付岗位/功能所需的完整外观范围，群体交付共同轮廓、制服/表面规律及必要成员差异，不限人类、生物或机械。
- `scenes`：需要稳定空间布局、固定结构、调度关系和环境身份的空间。
- `props`：可独立制作的物件、武器、设备、服装、载具、机甲或机械主体。

先判断是否需要资产，再判断人物是否必须维持专属视觉身份，最后选择唯一制作路线。重要配角、一次性反派等只要换一张脸会被观众理解为换人，就进入 `characters`；前台、服务员、保安甲乙、学生甲乙、工作人员等即使单独出现、有名字或台词，只要不需要固定面孔、可以由同功能人物替换，就进入 `extras`，不得因其是单人而排除。姓名、台词、物种称谓、剧情地位和出现时长都不能单独决定纳入或类别。只有纯背景、无法辨识且不需要控制外观的人员才排除；无法唯一分类或归并时写入 `exclusions` 说明原因。

## 旧资产归并与新形态

只查询候选名称命中的旧记录。更新旧资产必须沿用查询结果中的规范 `assetName`、`assetId`、`firstRequiredEpisode` 和 `firstRequiredOrder`，并提交保留旧有效信息的完整新版记录。

新主体或旧参考图无法在不冲突的描述下稳定复现的新形态才建立新资产。整体轮廓、解剖、完整服装体系、机械结构或空间身份发生改变且需要独立参考图时拆分；表情、姿态、普通天气、轻微污损、局部血迹和不改变整体设计的附件通常不拆。后文补充从一开始就存在的信息时更新旧记录，不倒推建立新形态。

同一主体的合法多形态必须使用共同主体名加不同形态限定，例如“赵德（宿舍便装形态）”与“赵德（崭新西装形态）”。它们可以共享剧中明确的主体称呼；这种共享用于一次查询命中该主体的全部旧形态，不属于不同主体的名称或别名冲突。查询结果已经存在同主体的一个或多个形态时，禁止再用 `assetId=null` 的无形态限定主体名称建立新资产：要么沿用命中的规范名称与 ID，要么在当前原文明示新完整形态时使用新的形态限定名称。只有主体名不同却共享称呼、因而无法确定是否同一身份时，才进入待确认。

## 资产记录字段

单集 `assets` 只写本集新增或修订后的完整资产记录，不复制未变化的旧资产。

- `assetId`：SDK 输出中，新资产固定为 `null`；旧资产使用查询所得 ID。固定 worker 会在正式写入新资产前移除 `null`，同步脚本再分配正式 ID。
- `assetName`：类别内唯一的规范名称；角色、生物与群演之间也不得重名。需要形态限定时写入完整名称。
- `productionNotes`：单集分析阶段固定填 `null`。全剧世界观总览完成后，最终视觉规格阶段才依据完整累计事实回填为脱离剧情上下文仍可直接理解的当前资产完整视觉定义；不得在单集阶段臆造。
- `scriptSetting`：只写剧本明确事实；信息不完整时以“其余信息剧本未标明”收束，不编造身份、能力或剧情。
- `inferenceBasis`：单集分析阶段固定填 `null`。全剧世界观总览完成后再回填，只解释世界观、环境、功能和身份如何约束必要的视觉补全；不复述剧本事实或制作说明。
- `aliases`：只保存剧中明确、用于跨集归并的称呼；没有时写空数组，不重复 `assetName`。
- `firstRequiredEpisode`：首次实际需要独立参考图的集数。新资产必须等于当前集；旧资产保持原值。
- `firstRequiredOrder`：同一数组在首次需求集内的首次制作顺序，从 1 连续编号；旧资产保持原值。
- `faction`：仅角色、生物和群演使用，格式为 `国家或组织｜具体归属（身份）`；场景和道具不得包含该字段。

本集允许没有新增世界观事实或资产，不得为填充数组虚构内容。

## 排除项与输出

`exclusions` 每项只能包含：

```json
{"item":"已检查但未登记的对象或判断","reason":"不纳入世界观或资产的具体原因"}
```

最终只返回固定 output schema 要求的嵌套 `analysis` 对象。生成当前集结果后立即停止，不读取下一集，不执行任何写入、累计、总览、Excel、队列或出图动作。

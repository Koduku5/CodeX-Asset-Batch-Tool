# KA 剧本资产流水线

仅处理调用方给定的一个项目根目录。剧本、`cache`、`输出`、队列和锁都必须位于该项目内，禁止读写其他项目。

## 运行边界

- 使用项目根内已固定的 `scripts/` 与 `assets/` 运行时快照。
- 将通用 Skill 版本与指纹写入任务回执；不把 Skill 复制成项目私有版本。
- 只执行已注册的固定动作。不接受网页传入的命令、路径、模型名或 Prompt。仅 `build-scoped-workbook` 接受服务端校验后的闭区间集数与固定五类资产类型参数。
- SDK Agent 可以读剧本并做语义判断，但禁止领取内置出图任务，禁止声称调用了 `image_gen`。
- 阶段失败时停止后续写入，保留可恢复 Cache 和受控日志。

## 按阶段披露规则

- 剧本切分只运行固定 Python 脚本，不启动 Agent，不读取任何 reference。
- 单集分析转交给独立的 [ka-episode-asset-analysis](../ka-episode-asset-analysis/SKILL.md)；单集 Agent 只完整读取该 Skill，不读取本 Skill、其他 reference、拆分/累计脚本、全剧总览、Excel 或出图规则。
- 单集分析写入、累计合并、资产 ID 分配和完成标记只运行固定脚本，不启动第二个 Agent；名称或别名身份冲突由同步脚本把完整候选草稿及首次需求顺序自动暂存到 `cache/待确认记录.json`，当前集仍正常完成。单集阶段的 `productionNotes`、`inferenceBasis` 保持 `null`，不得提前反推视觉规格。
- 全部单集完成后，世界观总览动作才读取 [worldbuilding-analysis.md](references/worldbuilding-analysis.md) 中的全剧综合规则；若仍有待确认项，流水线在视觉规格与制表前进入安全等待。人工在软件窗口逐项选择独立建档、合并已有或排除；固定脚本在最后一项决定后一次性正式纳入、更新结构化引用、紧凑整理资产 ID 并写入编号沿革账本，不重新调用模型。随后软件自动续跑固定视觉规格动作：本地脚本每次只提取一个累计资产的事实字段与最终世界观正文，SDK 只返回 `productionNotes`、`inferenceBasis`，脚本校验资产 ID 后原子回填并记录进度。
- 处理条件分支与队列前才读取 [prompt-catalog-architecture.md](references/prompt-catalog-architecture.md)。

## 流水线

1. 校验项目根、环境和单一剧本来源；来源变化时依指纹重建受影响阶段。
2. 按以下固定顺序启动逐集分析：
   1. 脚本拆分整部剧本。
   2. SDK 分析第 1 集。
   3. 脚本写入第 1 集分析 JSON。
   4. 脚本同步世界观事实与五类累计资产。
   5. 分配新资产 ID，并标记完成。
3. 第 1 集完成后，从上述第 2 项开始依次处理下一集；不重复拆分剧本。当前集未完成写入、累计、ID 分配与完成标记时，禁止启动下一集。
4. 全剧完成后分页汇总世界观。若 `待确认记录.json` 有未应用候选，固定检查点暂停后续步骤，由软件人工确认窗口处理；未全部处理前不得生成视觉规格、工作簿或出图队列。
5. 最后一项人工决定提交后，`resolve_pending_asset.py` 在同一事务中应用全部暂存决定、按首次需求顺序整理资产 ID、更新单集结构化引用并写入 `cache/资产编号沿革.json`。随后按“读取一个资产事实 → SDK 生成两个视觉字段 → 脚本原子回填 → 标记该资产完成”的固定顺序逐资产完成视觉规格。全部资产回填完成后才校验记录并生成 `输出/剧本资产制表.xlsx`。局部表请求也必须先完成全剧分析、完整世界观、人工确认和全部资产视觉规格；集数和类型只过滤正式工作簿中的资产行，世界观总览始终完整。
6. 工作簿只使用同一正式路径，生命周期只能是“无表 → 局部表 → 全剧表”。后续全流程在同一工作簿中补齐全集资产并按资产 ID 保留人工流程列；已有全剧表时必须拒绝缩回局部表，不生成单独的局部表文件。
7. 使用 Prompt Studio 已确认的风格、类别、参考图快照和提示词预设。条件分支根据累计资产中的正式 `productionNotes` 判断，只能从正式 `conditionModules` 候选中选择；每个 family 最多一个，不自创 ID，不用关键词硬编新路由。
8. 将每个最终队列 Key 的选择与当前 Catalog/注册表指纹校验后，原子写入 `cache/提示词分支匹配.json`。
9. 运行 `build_image_queue.mjs` 直接读取五类累计资产 JSON，按类别及 `firstRequiredEpisode → firstRequiredOrder → assetId` 建立最终 `cache/出图队列.json`；不重新解析或核对 Excel。断点续跑只依据单项输入、Prompt 配置和参考图指纹判断结果能否复用。
10. 返回结构化回执，只报告阶段、数量、指纹和阻断原因；不将完整剧本、制作说明、Prompt、队列项或绝对路径写入网页日志。

## 完成条件

只有目标阶段的正式脚本校验通过才返回成功。队列建立后停止；后续内置出图必须交给 `$ka-builtin-imagegen`。
